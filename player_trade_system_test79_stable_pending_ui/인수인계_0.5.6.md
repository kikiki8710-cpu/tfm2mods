### 2-2. 요구사항 1 — 영입 시즌당 1회 (성사만 소모)

```rust
const TRADE_SEASON_USAGE_KEY: &str = "trade_season_usage_v1";
fn current_recruit_season_key(db) -> Option<String>   // "{schedule.id}|{year}|{start}"
```

`mark_trade_season_used` 는 **`persist_trade_commit` 안에서만** 호출됩니다 —

소모 후에는 대상 선수의 트레이드 버튼이 **비활성 스타일 + 호버 툴팁**이 되고, 다른 선수는 영향받지 않습니다.

### 2-3. 요구사항 2 — 계약 현황 / 전체 협상 상황 (가장 오래 걸린 부분)

**결론부터: 행을 우리가 만들면 안 됩니다.** 게임이 우리 `TransferRequest` 로 **네이티브 행을 이미 만듭니다.**

세 번의 접근 변경:

1. ~~네이티브 행 clone~~ → 원본 선수의 신원이 따라옴(인수본이 막혔던 지점)
2. ~~`.ui` 템플릿 인스턴스화 + UI 주입~~ → 신원 문제는 풀렸지만 **여전히 화면에 안 보임**
3. ✅ **네이티브 행 사용 + 열 값만 덮어쓰기**

3번으로 간 결정적 근거는 트리 덤프였습니다:

```
contract.list          ScrollViewRunner  rect=296,202,1600,790
contract.list.contents EmptyRunner       rect=296,202,1600,0   lh=Pixel(0.0)   <- 높이 0
  L transfer_159_0     게임이 만든 행     rect=296,202,1605,44  (10열 전부 정상)
```

`.ui` 선언은 `height:900px` 인데 런타임 값이 `Pixel(0.0)` 입니다 = **게임이 실행 중 0으로 덮어씁니다.**
어떤 행을 넣든 그 안이면 클리핑됩니다. **주입이 안 보였던 이유도 이것 하나였습니다.**

조치:

- `nudge_collapsed_contract_lists` — 자식이 있는데 높이 0인 계약 탭 리스트의 `layout.normal.height` 를
  자식 높이 합으로 **매 프레임** 지정 (게임이 매 프레임 0으로 되돌리므로 상시 보정)
  ⚠ `set_dirty` 만으로는 재레이아웃이 안 걸립니다(1차 시도 실패로 확인)
- `overwrite_native_trade_rows` — 네이티브 행의 4열을 우리 값으로:
  이적료(제안 현금) / 협상 현황(우리 단계) / 협상 기한 / 조건 제의(`<보낼선수> 포함`)
- **행 id 규약이 탭마다 다릅니다**:
  계약 현황 `transfer_<athleteId>_<n>` · 전체 협상 상황 `ca_<athleteId>_<teamId>_<n>`
- `CONTRACT_UI_INJECTION_ENABLED = false` — 주입 코드는 **보존만** 하고 껐습니다(되돌릴 수 있게)

**제안 직후 즉시 표시** — UI가 읽는 것은 서버 `Database` 가 아니라 **`ClientDatabase`** 입니다(`ClientData::db()`).
서버에만 쓰면 다음 관리 갱신 때까지 안 보입니다. `data.db_mut()` 로 클라 DB 에도 선반영합니다
(`sync_client_transfer_request`). 서버가 정본이고 이건 표시용입니다.

### 2-4. 요구사항 3 — 프로필 첫 오퍼 + 신원 판별

죽어 있던 경로를 되살렸고, 그 과정에서 **신원 판별 결함**을 발견해 고쳤습니다.

구판은 표시 중인 선수를 트리에서 읽지 않고 **`player_detail` 노드 포인터** 일치로 판정했습니다:

```rust
(athlete_id != 0 && bound_instance == detail as *const Node as usize).then_some(athlete_id)
```

그런데 `player_detail` 에는 athleteId 캐리어가 **없습니다**(프로필 4개 전수 덤프 — 전부 `event_0`·`label_0` 순번).
신원은 **클릭 경로**에만 있는데 파서가 `view_detail_<id>` 하나만 봤습니다. 실제 프로필 오픈 경로는:

```
main.top.right.scout.contents.all_players.list.contents.candidate_159
```

⟹ 신원이 0으로 남아 ①대상 선수에 아무것도 안 뜨고 ②포인터 재결속 분기를 타면 **무관한 선수**에 붙었습니다
(실제로 일본리그 선수 프로필에 트레이드 상태가 뜨고 이적 협상 버튼이 사라졌습니다).
조치 = 게임 핸들러 테이블이 쓰는 선수 행 접두 전체를 인식:

```rust
const PROFILE_IDENTITY_PREFIXES: [&str; 5] =
    ["view_detail_", "candidate_", "transfer_", "recruit_", "resign_"];
```

스태프(`staff_`/`staff_ca_`)는 athlete 이 아니라 **일부러 제외**했습니다.

### 2-5. 거절 쿨다운 — 배선 + 규칙 변경

`check_cooldown` 은 정의만 있고 **아무 데서도 호출되지 않았습니다.** 즉 거절 뉴스가
"같은 제안은 X부터 가능"이라 약속해놓고 실제로는 아무것도 막지 않았습니다. 먼저 배선했고,
이어서 **규칙 자체를 바꿨습니다**(구멍이 있었기 때문).

구 규칙(`changeable` 이면 지문이 다른 패키지는 통과)의 구멍:

> 12억으로 거절당함 → 평가액이 뒤집힐 때까지 대기 → **0원 패키지** 제출 → 지문이 달라 쿨다운 통과

⟹ 판매자에게 **더 나쁜** 조건이 재제안으로 인정됐습니다. 현재는 **해제시각까지 그 선수에게 전면 차단**입니다:

```rust
fn ledger_gate(entry, _candidate_fingerprint, now) -> bool { now < entry.retry_at.as_str() }
```

클라이언트 선차단도 넣었습니다(버튼 단계에서 회색 + 사유). 서버 게이트와 **같은 함수 형태**로 유지해야 합니다 —
어긋나면 "버튼은 막혔는데 제출은 됨"이 됩니다.
견적 응답에 `cooldown_present/_fingerprint/_retry_at/_changeable/_exempt` 5줄을 실어 보냅니다.

⚠ **부수 변경**: `StatusOrInheritedSalaryUnacceptable`(선수가 위상·승계 조건 거부) 거절은 원래 **즉시 재시도 예외**였는데,
"해제시각 전까지 비활성" 지시에 맞춰 **이것도 막았습니다.** 예외를 되살리려면 `cooldown_hint_blocks` 의
`exempt` 분기만 복구하면 됩니다.

### 2-6. 모달 UI

## 5. 남은 과제 (해결 방법 포함)

### 5-1. ⬜ 견적이 0으로 붕괴하면 범위가 `0~0` 이 됨 (밸런스 판단 필요)

**증상**: 추가 현금 제시 범위가 `0억 0천 ~ 0억 0천` 이 되어 **0원만 입력 가능**. 웃돈을 얹을 수 없습니다.

**원인**: 상대가 받는 선수가 내주는 선수보다 비싸게 평가되면(`incoming_ratio > 1.0`, 실측 1.124)
`policy_accepts(cash=0)` 이 참 → `required_units == 0` → `stable_obscured_cash_range` 가 `(0,0)` 반환.

**해결안**: `stable_obscured_cash_range` 의 `if required_units == 0 { return (0,0,0,0) }` 를
`(0, 상한)` 으로 바꿉니다. 상한은 이미 인자로 들어오지만 현재 미사용인 `_budget_units` 를 쓰거나,
대상 선수 평가액 기반 값을 새로 넘기면 됩니다.

**판단이 필요한 부분**: 가치가 역전됐을 때 **공짜 트레이드가 성립하는 것 자체**가 의도인지.

### 5-2. ⬜ 평가액 변동폭이 큼

같은 세이브·고정 능력치인데 이틀 사이 **Doran +22.9% / Flandre +6.0%** 로 서로 다르게 움직였습니다
(비율 0.832 → 1.124 → 0.969 → 0.836). 그 결과 요구 현금이 10억대 ↔ 0원을 오갑니다.

**원인 후보**: `fair_fee` 가 부르는 것은 **게임 자체 함수**입니다:

```rust
calculate_athlete_fair_transfer_fee_at(athlete, market, region_id, db.time, GameModeKind::Moba)
```

인자에 **이적시장 상태와 날짜**가 들어가므로 능력치가 고정이어도 값이 움직입니다.

**실측 절차**(진단은 이미 들어가 있어 추가 작업 불요):

1. 새 세이브 1일차에 **시간을 넘기지 않고** 모달을 두 번 연다 → 값이 같으면 랜덤 요소 없음
2. 하루만 진행 후 다시 연다 → 일간 변동폭 실측

로그 이벤트 = `trade_quote_threshold_inputs`
(offered_value / target_value / effective_ratio / zero_cash_accepted / requester_cash).

### 5-3. ⬜ 진단 로그가 과다

한 판에 수만 줄이 남습니다. 배포 전 정리 대상:

- `trade_quote_threshold_inputs`, `native_trade_row_columns`, `native_trade_row_id_probe`,
  `contract_list_collapsed_nudged`, `cash_input_lock_state`
- 트리 덤프 2종은 이미 상수로 꺼져 있습니다: `CONTRACT_TREE_DIAGNOSTIC_DUMP_ENABLED`,
  `PLAYER_DETAIL_DIAGNOSTIC_DUMP_ENABLED` (재조사 시 `true` 로)

### 5-4. ⬜ `async_trade_status_query_timeout` 간헐 발생

관측 표본에서 341건 중 17건. 기능 영향은 확인되지 않았습니다(응답이 다음 프레임에 도착).
**해결 방향**: 재시도 간격/프레임 한도를 조정하거나, 타임아웃을 경고 대신 무시 처리.

### 5-5. ⬜ 전체 협상 상황 탭에는 없는 열

`ca_<id>_<team>_<n>` 행에는 `contract_limit`·`action` 열이 **구조적으로 없습니다**(8열).
덮어쓰기가 그 두 열에서 `false` 를 반환하는 것은 정상입니다.

### 5-6. ⬜ 트레이드 버튼 클릭이 부모 컨테이너로 잡히는 근본 원인

현재는 `.data.row2` 컨테이너 클릭을 진입 클릭으로 채택해 **우회**하고 있습니다
(`TRADE_ENTRY_ACTIVE && item.is_empty() && path.ends_with(".data.row2")`).
row2 의 실제 컨트롤은 전부 자식이라 컨테이너 클릭에 원래 의미가 없어 안전하지만,
왜 버튼 자신이 잡히지 않는지는 규명하지 않았습니다.

### 5-7. ⬜ 조건 제의 열의 글자 스타일

`Doran 포함` 라벨은 같은 행의 `contract_state.text` 를 복제해 만듭니다. 표시는 되지만 색·정렬이
그 칸 기준과 다소 다릅니다.

⚠ **`action.delegated_label` 을 쓰면 안 됩니다** — 그 라벨은 `set_runner_text` 가 먹지 않습니다
(직접 쓰기도, 복제도 둘 다 화면에 안 나왔습니다). 스타일을 맞추려면 복제한 노드의
`style` 배열(normal/hover/active/disabled)을 직접 지정하는 쪽이 확실합니다.

## 6. 작업하실 때 도움이 될 것들

- **모든 변경점은 `[PORT056]` 태그**로 찾을 수 있습니다 (`grep -n PORT056 src/lib.rs`, 현재 117곳).
- **UI 주입이 "붙었는데 안 보인다" 면 부모 체인의 `rect` 와 `layout` 부터 찍으세요.**
  자식만 보면 영원히 안 보입니다. 저는 이걸로 세 라운드를 잃었습니다.
- **로그의 이벤트 이름은 화면 증거가 아닙니다.** `rendered` 가 찍혀도 화면은 비어 있을 수 있습니다.
- **`downcast` / `TypeId` 는 모드 cdylib ↔ 게임 경계를 넘지 못합니다.** 런너 판별은
  `type_name()` 문자열 비교 + 포인터 변환으로 해야 합니다(`runner_base`).
- **같은 id 노드가 2개일 수 있습니다**(`.ui` 템플릿 + 런타임 인스턴스). `pts_cash_input` 이 그랬고,
  `set_node_disabled(ui, id, ..)` 가 엉뚱한 쪽을 잡아 입력칸이 잠긴 채 남았습니다.
  런타임 인스턴스는 **패널 루트 안쪽으로 범위를 좁혀** 찾으세요.
- **게임이 매 프레임 다시 쓰는 셀과는 싸우지 마세요.** 우리 노드를 하나 넣는 편이 빠릅니다.

# tfm2_ai_adjust 바이트패치 **앵커 등록부**

> 앵커 = "그 주소가 `prefix + 기대 즉치`로 **바이트 정확히** 맞던 exe(또는 git 리비전)".
> 마이그의 출발점이다. **앵커가 없으면 재핀은 추측이 되고, 추측한 오패치는 크래시 없이 AI를 왜곡한다.**
>
> ⚠2026-09-04 실측: 앵커를 매번 다시 찾느라 **git 리비전 34개 × exe 12개**를 훑었다.
> 그 결과를 여기 적어 둔다 — 다음 버전은 "앵커 → 유사도 사영 → 바이트 검증"만 돌리면 된다.

## 4. ★다음 버전 마이그 절차 (도구 = 이 폴더)

```
1) python audit_all.py            # 4형식 + 정적테이블 전수 감사 → 죽은 사이트 목록
2) python anchor_find.py          # git 리비전 × 전 exe 교차 대조 → 앵커 스냅샷
3) python migrate.py <앵커>       # owner 유사도 사영 → 사이트 사상 → 바이트 검증
4) python orig_sync.py            # ★orig_table 이관·채움 (이걸 빼면 패치가 안 나간다)
5) 빌드·배포 → 게임 실행 →
   imm_guard_summary.txt 의 blocked=0 · unknown=0 + imm_unknown.txt 미생성 확인
   ⟹ imm_unknown.txt 가 남으면 그 자체가 **표 누락 명세**다(from_unknown.py 로 흡수)
```

⚠**완료 판정은 "감사 통과"가 아니라 `blocked=0 · unknown=0`이다.**
가드(`orig_guard_ok`)는 2026-09-02부터 **fail-CLOSED** — 표에 없는 RVA 는 거부한다.
사이트만 재핀하고 표를 안 옮기면 **바이트는 맞는데 패치가 하나도 안 나간다**(무증상).

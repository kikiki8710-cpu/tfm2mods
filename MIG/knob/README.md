## 2. 판정 기준 (근거가 강한 순)

1. **바이트 정확 일치** — `prefix + 기대 즉치`. 이게 최종 관문이고, 통과 못 하면 무조건 폐기.
2. **유사도 여유** — owner 후보 전원과 재서 `1위 r ≥ 0.70` **이고** `1위−2위 ≥ 0.03`.
   ★유일성은 선언하는 게 아니라 **측정하는 것**이다.
3. **동률 클론** — `r=1.000` 이 여럿이면 가르지 말고 **전부** 채택(소스가 클론을 전부 패치하는 설계).
4. **구조 제약** — `lard = larn 의 +11B 짝`, `cmp`+`mov` 쌍, 상수 사다리(`49,65,29,40,17,25,10`) 등.
   소스 주석에 적힌 구조가 곧 지문이다.
5. **원본 즉치 서명** — 앵커가 없을 때. 단 **즉치가 희소할 때만**(`b1(k,5)` 는 전역 1,512히트 = 무의미).

## 3. ⚠함정 (전부 2026-09-04 에 실제로 밟은 것)

- **prefix 도 바뀐다.** 주소만 갈면 `p!` 가 **조용히 skip** 한다. 재핀 결과는 **주소+prefix 한 세트**로 받을 것.
- **감사 파서는 "내가 아는 형식만" 읽는다.** 하루에 네 형식을 놓쳤다.
  판정 전에 **소스에서 주소가 등장하는 모든 구문 형태를 먼저 열거**할 것.
- **파서가 못 읽으면 "판정 불가"로 남길 것.** 튜플 루프 미지원이 앞선 루프 주소를 갖다 붙여
  **없는 사이트 5건을 만들어냈다**.
- **생사·앵커 판정에 prefix 만 쓰지 말 것**(prefix+즉치). 잔여 48주소는 23본 exe 어디서도 FULL 일치 0건이었다.
- **소스가 스테일하면 소스의 과거를 봐라** — `git log -S "<노브명>" --all -- <파일>`.
  주석의 `←0.5.3` 이력과 같은 계열 자료인데, 주석이 없는 줄에도 git 은 남아 있다.
- **부분 마이그가 상태를 더 나쁘게 만든다.** 통째로 이동하는 계열은 **스냅샷째** 옮길 것.
- **커버리지 100% 는 분모부터 의심.** 튜플 첫 원소만 읽어 `mov` 짝이 분모에서 빠졌던 적이 있다.
- **검증 두 개가 같은 가정을 공유하면 함께 눈이 먼다**(정적 감사·런타임 가드가 나란히 통과시킨 구멍).
- `pskip!` 은 함수마다 `macro_rules!` 로 정의된다. 정의보다 앞줄에선 빌드 실패 — 死코드는 **주석 처리**.
- 검증 도구가 못 다루는 입력은 "실패"가 아니라 **"미지원"**으로 출력할 것(폭 2바이트 미지원이
  "섹션 밖"이라는 틀린 사유를 만들어 두 번 헛짚었다).

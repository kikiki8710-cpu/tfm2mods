## 1. ★표적이 바뀌었다 — `open` 사냥이 아니다

`open` 이 **63 → 11건**까지 줄었다. 배치당 1~5건뿐이라 시간이 남는다. **그 시간을 여기 써라:**

| 배치 | `ev1` 런타임 | `ev2` 오라클실행 | `ev3` tcx·MIR·DWARF | `ev4` IR독해 | `ev5` 추론 | **ev≥4 비율** |
|---|---|---|---|---|---|---|
| A (00~04) | 0 | 3 | 8 | 183 | 2 | **94.4%** |
| B (05~09) | 0 | 5 | 19 | 168 | 0 | **87.5%** |
| C (10~14) | 0 | 5 | 10 | 239 | 0 | **94.1%** |
| D (15~19) | 0 | **0** | 18 | 198 | 0 | **91.7%** |

**명세의 87~94% 가 「IR 을 읽어서 그렇게 보인다」 수준이다.** 실행으로 확인된 행은 전체 858행 중 **13행**.
⟹ ★**5차의 1순위 = `ev4` 를 `ev2` 로 끌어올리는 것.** 그 과정에서 틀린 게 나오면 그게 이번 라운드의 성과다.
⟹ **배치 D 는 `ev2` 가 0 행이다.** 4차에 D 가 「9축 전부 무관」을 뒤집은 것도 바로 이 공백에서 나왔다.

**우선순위 정하는 법**: 재현에 실제로 쓰이는 것부터. `knobs`(노브 = 개입 지점) → 판정 임계 `consts` →
분기를 가르는 `mem` 오프셋. 장식적인 오프셋(좌표·길이)은 뒤로.

## 2. 4차 이후 달라진 것 (중복 작업 방지)

### ① 4차 정정은 전부 반영됐다 — **그리고 그걸 기계로 확인할 수 있다**
```bash
cd /c/tfm2mods/MIG && PYTHONIOENCODING=utf-8 python -X utf8 _spec/audit4.py
```
배치 A/B/C/D 보고서의 36항목을 `specs20_v3.json` 과 문면 대조한다. 현재 **미반영 0 · STALE 0 · ev불일치 0**.
⚠**4차 배치B 가 「3차 정정이 전부 반영됐다」를 거짓으로 적발했다.** 그래서 이번엔 주장 대신 도구를 준다.
**너희 정정도 5차 종료 후 같은 방식으로 감사된다** — 그러니 보고에 **고유 문면**(값·주소·줄번호)을 남겨라.

### ② 게이트가 G1~G10 으로 늘었다
```bash
PYTHONIOENCODING=utf-8 python -X utf8 specgate.py            # 전량
PYTHONIOENCODING=utf-8 python -X utf8 specgate.py --only 14  # 한 함수
PYTHONIOENCODING=utf-8 python -X utf8 specgate.py --gate G7  # 한 게이트
```
| | 막는 것 |
|---|---|
| G1~G6 | 자기모순 / 호출부 전수 / 형제 함수 / 술어 시그니처 / `sig` 정본 대조 / `logic` 미반영 |
| **G7 과열림** | 이미 해소된 항목이 `open` 에 남음. ★**`shared` 까지 본다**(초판은 안 봤고, 그래서 `03` 이 5차 직전까지 열려 있었다) |
| **G8 표에 옛 값** | G6 의 **역방향** — `logic` 은 고쳤는데 `mem`/`consts`/`knobs` 에 옛 값이 남음 |
| **G9 callees 오염** | `logic` 이 메서드를 필드로 적어 자동수집이 놓침 |
| **G10 class 오분류** | 확정된 사실이 `미탐색` 자리에 앉음 |

**제출 조건 = G1~G8·G10 이 0.**
`G9` 는 두 등급이다 — `★강함`(enum 필드를 관통하는 경로 = 필드일 수 없다)만 실오류이고, `손확인`은
Rust 에서 필드 `line` 과 메서드 `line()` 이 공존해 기계로 못 가르는 목록이라 **눈으로 보고 넘기는 게 정상**이다.

### ③ 판정 어휘가 **4종**이 됐다 — `notes[]` 를 파지 마라
| 분류 | 뜻 |
|---|---|
| **미탐색** | 불가가 아니라 **아직 안 읽음**. "더 파면 나온다"는 약속이다 |
| **재료 부재** | 이 재료에 실체가 없음 — **탐색 범위를 열거해야 한다** |
| **표기 불가** | **동작은 확정**, 소스 표기만 복원 불가 |
| ★**사실 서술** | **물음이 아니다.** 확정된 관측·기록 ⟹ `open[]` 이 아니라 **`notes[]`** |

★**`notes[]`(8건)는 파지 마라. 틀렸다고 보면 반증하라.** 이 둘은 다르다 —
"미탐색이니 조사한다"가 아니라 "확정됐다는데 정말인가"다.

⚠**범위 한정된 「불가」는 재료 부재가 아니다.** "이 함수만으론 확정 불가"·"이 범위에서 확인 불가"는
**호출부·생성부·피호출자를 안 본 것**이고 전부 도달 가능하다. 5차 직전에 이 오분류 3건을 고쳤다.
**「미탐색을 불가로 적는 것」이 이 파이프라인 최악의 오염이다** — 다음 세션이 시도조차 안 한다.

### ④ 오라클 정본 템플릿에 함정이 5개 등재됐다 — **복사해서 시작하라**
`MIG\_verify3\TEMPLATE.rs` (머리말 ①~⑤ 를 **끝까지 읽어라**) · 빌드 = `sh MIG\_verify3\build.sh <내프로브.rs>`

①`GameSetting::default()` 는 숫자 44필드가 0 → `real_setting()` 을 써라(`height==0` 이면 u64 언더플로).
②`start_game()` 뒤에 `init_tower()`/`init_nexus()` 를 부르면 타워가 2배가 된다.
③★★**TLS 메모를 쓰는 함수는 한 프로세스에서 반복 측정하면 안 된다.** `check_kill_die_tick` 은
 `thread_local!(RefCell<DieTickCache>)` 이고 **캐시 키에 엔티티 id 만** 있어 hp·스탯을 바꿔도 **첫 값이 재생**된다.
 **케이스당 프로세스 1개**(참조구현 `_verify4\D\body_o2.rs`). **징후 = ①세계를 바꿨는데 결과 불변
 ②호출 순서를 바꾸면 값이 뒤집힘.** 「판별력 부재」라고 쓰기 전에 프로세스를 갈라 다시 재라.
④실전 `ChampionInfo::default()` 는 **액션 파라미터까지 0** → `AttackEffect`(72B, 전 필드 pub) 직접 조립.
⑤미니언은 자동 생성 안 된다 → `minion_wave_setting` 16필드 + `melee/range_minion` 주입 + `run_tick` 600틱.

⚠**과거 프로브를 인용할 때는 그 프로브가 `setting_ok()` 를 찍었는지 먼저 확인하라.** 3차가 이 템플릿을
정본화했는데 3차 자신의 앵커 프로브가 그걸 안 쓰고 있었다.

### ⑤ 오라클 접근 범위가 넓어졌다
**모듈 경로로 「`pub(crate)` 라 막힌다」고 단정하지 마라** — 크레이트 루트 재수출 항목은 `pub` 이다

## 4. 정본과 우선순위

`specs20_v3.json` 안에서 **어긋나면 이 순서로 믿어라**:
1. **`mem`**(오프셋) · **`consts`**(상수) · **`callees[].sig`**·**`sig.tcx`**(시그니처) ← 기계 생성/정본
2. `logic`(산문) ← 사람이 씀. **1과 어긋나면 `logic` 이 틀린 것이다**
3. `history[].was` 는 **정의상 옛 주장**이다. 현재 결론은 `now` 쪽이다

재료 라우팅 = **`MIG\METHOD_MAP.md §0`**(30초 표) / 추출법 = `IR_TOOLKIT.md` / 규격 = `SPEC_GUIDE.md`.
⚠**`_gaibc` 에 `declare` 만 있으면 `_gcbc`/`_gvbc` 에서 `define` 을 찾아라** — 1~6차에서 17건이
"본문 없음"으로 포기됐는데 전부 `_gcbc` 에 있었다.
⚠★**오라클을 돌리기 전에 `_gaibc` 에 `define` 이 있는지 먼저 봐라.** 4차 최대 발견(「9축 전부 무관」이
캐시 아티팩트였다)의 근본 원인은 3차가 본문 존재를 확인하지 않고 오라클 이분탐색만 한 것이었다.

**불변 게이트는 절대 수치가 아니라 `오귀속 0 · 밀림 0` 이다.** 총 건수는 명세가 자라면 당연히 변한다.
`--prose` 는 `~~취소선~~`(§7 이 남기라고 요구하는 옛 값)을 **마스킹**하고 그 수를 `masked` 로 찍는다 —
조용히 억제하지 않으니, `masked` 가 늘었으면 정정을 쓴 것이고 `오귀속` 이 늘었으면 진짜 오귀속이다.

**오프셋을 하나라도 적었으면 `--prose <내보고서.md>` 를 제출 전에 돌려라.**
⚠**한 행에 오프셋을 묶지 마라**(`0xc8/0xd0` 같이). 기계 검사가 무력화된다 — 4차 D-E5 가 그 건이다.

## 6. 산출물 규칙 (★경합 방지)

- **너의 산출물은 `MIG\_verify5\<배치문자>\` 안에만 둔다.** 다른 배치 폴더를 읽지도 쓰지도 마라.
- ⛔**`_spec\specs20.json` · `_spec\specs20_v3.json` 을 절대 수정하지 마라.** 읽기 전용이다.
  정정은 **JSON 경로로 보고**하고, 반영은 메인 세션이 한다(v3 는 생성물이라 직접 고치면 다음 빌드에 날아간다).
- ⛔`distruct.json` · `dienum.json` 도 수정 금지.
- 보고서 정본 = `MIG\_verify5\<배치>\<배치>5_REPORT.md`.

### 보고 형식
1. **결론 한 줄** — 실오류 N · 판정반전 N · 새 발견 N (0 이면 0 이라고 써라)
2. **정정 목록** — `/specs[i]/<필드>[j]/<키>` 경로 + `구 → 신` + **근거**(파일:줄 / 오라클 진리표 / 실행 결과)
3. **ev 상향** — `ev4 → ev2` 로 올린 행 목록(이번 라운드의 주 산출물이다)
4. **표본 재확인** — `ev<=3` 을 다시 재서 뒤집힌 게 있나(있으면 그게 사고다)
5. **게이트 결과** — §5 명령들의 실측 출력
6. **내 지시문의 오류** — 브리핑이 틀렸으면 지적하라. 4차에 네 배치가 전부 내 기준선 오류를 잡았고
   그게 가장 유용한 피드백이었다

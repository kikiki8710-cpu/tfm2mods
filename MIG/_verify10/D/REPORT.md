## 8. 내 지시(도시에)의 오류 — 6건 (`brief_errors[]` 와 동일)

1. ★**§5 의 「새 항목 추가(append)는 구현이 없다」가 거짓.** `applypatch.py:242~277` 에 `op:"insert"`/`"delete"` 가
   있고 그 코드 주석이 「9차 실측」을 인용한다(이미 쓰였다). **유저 지시문 쪽은 insert 문법을 정확히 주는데
   도시에 본문만 낡았다** — 도시에만 읽은 배치는 이번 라운드 최대 수확(§4)을 기계 적용 불가로 접었을 것이다.
2. ★★**`applypatch.py` 의 insert 경로 실버그.** `op=="insert"` 는 `arr, _ = resolve(cont, field, 0)` 로 배열을 고르는데
   `field` 가 `mem`/`knobs` 면 경계 계산이 **인덱스 0** 기준이라 **항상 앞쪽 배열**(`reads`/`knobs`)이 선택된다.
   ⟹ 지시문이 준 예시 `{"op":"insert","path":"/specs[i]/mem","at":N}` 은 `at` 이 아무리 커도
   **`writes` 가 아니라 `reads` 끝에 꽂힌다**(조용한 오삽입). 이번엔 `/specs[18]/writes` 로 우회했다.
   고침 = insert 일 때 `at` 을 먼저 경계 계산에 태우거나, `mem`/`knobs` insert 를 거부하고
   `reads`/`writes`/`new_knobs` 를 요구할 것.
3. ★**`G13`(`whereline.py`)의 사각지대 3종** — 이번 `where` 오류 **11건 중 10건**이 여기로 샜다.
   ①백틱 인용이 없으면 **줄이 존재하는지만** 본다 ②`m09.ll:38724·39066` 처럼 **두 번째 이후 줄번호에 파일 접두가
   없으면 아예 후보로 안 잡는다**(39066 은 실제로 **빈 줄**) ③`m13.ll 33724~33728` 같은 **범위의 끝값**을 안 본다.
   최소 개선 = 백틱이 없어도 `where` 문장 안에 `icmp/store/switch/mul/gep/phi/call` 토큰이 있으면
   그 줄(±2)에서 요구. **이번 10건은 그 규칙 하나로 전부 잡힌다.**
4. ★**§4-b 의 무검사 축 목록이 실제 위험을 못 짚었다** — 셋 다 표본에서 불일치 0 인데
   `closed[]` 에서 15건이 나왔다. 그리고 그 축은 **기계로 셀 수 있다**(§3 의 G20 제안).
5. **파일 크기가 전부 ~30% 과소.** 실측 바이트: `spec_15` 40,733 / `16` 39,389 / `17` 34,791 / `18` 43,358 /
   `19` 28,487 / `DOSSIER_D.md` 13,477. 「60KB 넘는 파일을 한 Read 로 읽지 마라」는 한도를 주면서
   한글 3바이트를 문자 수로 센 값을 같이 주면 판단이 어긋난다(CLAUDE.md §8 에 같은 바이트↔문자 혼동이 이미 기록돼 있다).
6. **`callees[]` 의 성질 설명이 틀렸다.** §3 이 「tcx 자동 생성」, §4-b 가 「경로·시그니처는 무검사」라 하는데,
   실제로는 v2 `calls[]`(사람이 쓴 실호출 목록)의 **leaf 이름으로 tcx 를 조회한 후보 목록**이다.
   「빠진 호출이 있나」를 `callees[]` 로 물으면 구조적으로 오탐이 난다 — **물어야 할 정본은 `calls[]`** 다(§6-1·2).

### 부수: `applypatch` 출력 문구

`--dry` 가 insert 4건을 **「★적용 실패 4건 — 조용히 넘기지 않는다」** 머리 아래에 찍는다.
내용은 실패가 아니라 「⚠삽입 — 뒤 인덱스가 밀렸다. 끝나고 `--restamp` 를 돌려라」 경고이고,
바로 아래 집계는 `정정 37 성공 / 0 실패` 다. **머리와 집계가 서로 모순되는 출력**이라
다음 배치가 「내 patch 가 4건 거부됐다」로 오독하기 쉽다 → 경고는 별도 머리(`⚠주의`)로 분리할 것.

### ★메인 세션이 이 patch 를 붙일 때

`/specs[18]/writes` 에 **4행을 삽입**하므로 `18` 의 `mem` 인덱스 **12 이후가 전부 밀린다**.
도구 경고대로 **적용 직후 `--restamp`** 를 돌려야 `auditrounds` 가 STALE 을 내지 않는다.

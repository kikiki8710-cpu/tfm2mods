## 2. 근본 원인 — 한 문장

**"이 모드에서 버전이 바뀌면 갱신해야 하는 지점"의 전수 목록(매니페스트)이 어디에도 없었고,
매번 소스 스캔 휴리스틱 + 기억 + 636KB 이력 문서에서 즉석 재구성했다.**

### 2a. 대상 목록이 없었다
- MIGRATION.md §4 "모드별 체크리스트" = **0.4.x 시절 3모드**(ui_inject·item_editor·scrim, 전부 현재 죽음).
  현행 T1 모드의 체크리스트는 **0개**.
- 대상 집합을 "게임 mods 폴더의 설치 모드"로 잡음 → **ui_kit**(dll 없는 공유모듈)과
  **meta_item_delegate**(mod_info 유실로 미인식)가 집합 밖 = 사고 1·2·9.

### 2b. 소스 스캔 휴리스틱의 사각지대가 7종+
`const NAME: usize = 0xRVA;` 만 잡는 스캔으로는:
① 함수시작 아닌 중간 사이트 ② .rdata 주소 ③ 코드 인라인 imm ④ 여러 줄 배열
⑤ 공유모듈 ⑥ 콜사이트 대응(전역 인덱스 오류) ⑦ **인라인 리터럴**(`rva == 0x8404e1`)
— 이번 세션에서 하나씩 **사고를 겪으며** 발견. 사각지대를 개별 패치하는 방식 자체가 한계.

### 2c. 기계 검증이 없었다
- sig 가드는 fail-safe(틀리면 **조용히 스킵**) → stale 이 크래시가 아니라 **침묵 기능정지**로 나타남(사고 6).
- "마이그 완료" 판정이 재빌드 성공 = 컴파일 통과였지 "전 주소가 신 exe 에서 유효"가 아니었다.
- 낡은 진단 로그(08-03 `hl=true`)를 현행 증거로 오독 — 로그도 검증 수단이 못 됐다.

### 2d. 이력 누적이 정본을 파묻었다
- MIGRATION.md **636KB**, §7 은 세션별 append(§7.2-A1~A14…). "item_tactics 가 뭘 필요로 하나"를
  알려면 수십 개 섹션을 읽어야 했고, 실제로는 아무도(나 포함) 안 읽고 소스를 다시 스캔했다.
- 기록이 많을수록 "이미 다 됐다"는 착각을 강화 — 유저 진단 그대로.

## 3. 재발 방지 — 새 체계 (MIG\)

**원칙: 마이그 = "매니페스트의 각 엔트리를 새 버전에서 찾는 것". 소스 스캔은 매니페스트
누락 검출용 보조로 강등.**

1. **`MIG\manifest\<MOD>.json`** = 모드별 버전 민감 지점 전수 목록(기계 정본).
   엔트리 = 이름·파일:라인·종류(FN_START/MID/RDATA/INLINE/BYTE_PATCH/OFFSET)·현행값·버전·
   **현행 exe 에서 채록한 검증 바이트**·재탐색 방법.
2. **`MIG\mig_verify.py`** 3중 검사:
   - `check`: 전 엔트리를 exe 와 대조 → 엔트리별 PASS/STALE. **패치 직후 1회 실행 = 깨진 곳 전수 목록.**
   - `coverage`: 소스의 RVA 대역 리터럴 중 매니페스트에 없는 것 검출(사각지대 ①~⑦ 통합 방어).
   - `dups`: 같은 값이 여러 모드에 있으면 연동 그룹으로 보고(0x1788 로컬 복사본 방어).
3. **마이그 절차**(MIG\README.md): 패치 → `check` 로 STALE 목록 → 엔트리별 재탐색(방법 필드대로)
   → 소스+매니페스트 동시 갱신 → `check` 전 PASS + `coverage` 클린 = 마이그 완료 정의.
4. **구 자료 아카이브**: MIGRATION.md 이력은 `ANA\_archive\` 로, 파일 자체는 슬림 포인터로 재작성.
   mig05x 스크립트 35종도 아카이브(현행 엔진 `_mig057.py` 계열만 유지).

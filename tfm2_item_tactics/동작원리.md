# tfm2_item_tactics — 동작 원리 (v2.8.0 · 게임 0.5.4)

> 이 문서는 "현재 실제로 돌아가는" 경로만 설명한다. RVA 값은 **0.5.4 기준**이며 패치 때마다 바뀐다
> — 항상 소스의 상수(`lib.rs`·`ui_inject.rs`)가 정본이다. English version: `HOW_IT_WORKS.md`.

## 1. 이 모드가 하는 일

- 아이템 슬롯 **3 → 4** 확장 (`4items.cfg`의 `slots = 4`, `3`이면 3칸 유지 + 지정만)
- 개인전술 화면에서 **슬롯 1~4 전부에 아이템 지정**(바닐라 카테고리 + 모드 아이템, 내 팀만 적용)
- 4번째 슬롯을 비워두면(Auto) **아이템 신경망으로 자동 추천**
- 경기 중 **4번째 슬롯 아이콘 + 툴팁** 표시 (게임은 원래 3칸만 그림)
- 조합테스트에서는 블루/레드 **진영별로 따로 지정** (일반 경기 지정과 분리 저장)
- 비활성화된 아이템 모드의 아이템은 드롭다운에서 자동 제외

## 2. 훅 지도 — 게임 어디에 끼어드는가

| # | 대상 (0.5.4 RVA) | 방식 | 역할 |
|---|---|---|---|
| H1 | UI 로더 `0x2e35d0` / 파서 `0x1a3ce0` | 트램폴린 detour (`ui_inject.rs`) | 전술·훈련 화면 로드 시 4번째 슬롯 **드롭다운 노드를 append 주입**(타 모드 노드 보존) |
| H2 | 드롭다운 셋옵션 `0x1c1ad0` | 게임 함수 호출 | 드롭다운 옵션 구성 — 바닐라 6스탯+Auto(게임 i18n 참조로 자동 현지화) + 활성 모드템 목록 |
| H3 | 경기 launcher `0x13b53d0` | 진입 detour (최소 본문: 원자연산+VEH 읽기만) | 경기(sim) 시작마다 1회 발화. ①화면 경기면 **seed 캡처**(`LIVE_SEED`) ②retaddr로 경기 종류 판별(화면/조합테스트/배경) ③**대회 배경이면 TN 디스크립터 캡처**(§5) |
| H4 | seed-ctor `0x14e16d0` | 진입 detour | 화면 경기의 **provider 포인터** 캡처(`RENDER_PROVIDER`) — buy 때 is_live 대조 재료 |
| H5 | **buy `0xe767e0`** | 진입 detour | ★**주 주입 지점** — §3 |
| H6 | GameView update `0xaa06c0` | 진입 detour | 경기 중 뷰모델 직독 → **4번째 아이콘 노드 직접 그리기** + 마우스오버 시 게임 툴팁 show 함수(`0x236dc00`, 인자 11개)를 그대로 호출 |
| P1 | owned cap 바이트패치 (`cmp …+0x448, 3`의 imm → 4) | 상시(=mode 4) | 게임이 "3개 보유하면 그만 산다"는 상한을 4로 |
| P2 | gate3 바이트패치 (resolver 내 `jbe`) | 상시(=mode 4) | 4번째 슬롯도 빌드업 경로에 태움 |

멀티모드 공존: launcher 등 다른 모드(serpen)와 겹치는 진입부는 **체인 후킹**(외부 훅의 movabs 타깃을
트램폴린에 담아 순차 발화)으로 공존한다. 설치는 늦게(post_update) + 1회 확정.

## 3. 주입이 일어나는 구간 — buy 디투어 상세

게임 sim에서 **선수가 아이템을 사려는 순간마다** buy 함수가 불리고, 우리 detour가 먼저 돈다:

1. **경기 식별**: `provider(r9)+0xeb28`의 seed를 읽어 `LIVE_SEED`와 대조 → 화면 경기(is_live) 여부.
2. **팀 판정** (§4) — 내 선수가 아니면 아무것도 안 하고 원본으로 통과(passthrough).
3. **목표 빌드 주입**: 내 선수 확정 시 athlete의 build Vec(`+0x480/+0x488/+0x490`)에서
   - 슬롯 0~2: 유저 지정 아이템의 카탈로그 인덱스를 write. 단 **`owned <= 슬롯index`인 칸만**
     (이미 산 아이템은 절대 안 건드림).
   - 슬롯 3: 지정이 있으면 그 값, Auto면 **신경망 shadow-call**(`itemnet forward 0x145a680`,
     5-feature 채점)로 후보 중 최고점을 write.
4. **실제 구매는 게임 로직 그대로**: 게임의 buy resolver가 이 목표를 향해 t0→t4 자연 빌드업한다.
   모드는 "목표"만 바꾸고 구매·골드·타이밍엔 손대지 않는다 (P1/P2 패치가 4개 보유를 허용).

즉 주입 = **build[] 목표 덮어쓰기 1곳**이 전부이고, 나머지는 게임이 알아서 산다.

## 4. 팀 판정 — 판정 소스 3개의 OR 결합 (하나만 걸려도 주입)

| 소스 | 적용 경기 | 원리 |
|---|---|---|
| ① scene side | 화면 경기 | db의 매치 정보(`+0x17A8`/`+0x17C8` 두 팀 id + `+0x1900` is_team1_blue) 직독 → 내 side 계산 → athlete side(`+0x810`)와 대조. 1/256 샘플로 ②와 교차검증 상주 |
| ② aid 멤버십 | 배경 sim 전반 | `athlete_id(+0x800)` ∈ 내 팀 선발 로스터(`MY_ATHLETES` = db.team(pid).last_starting) |
| ③ TN 디스크립터 | **대회 배경 sim** (v2.8.0 신규) | §5 — 경기 생성 시점에 두 팀 id·side를 확정, ②가 놓친 선수(교체 출전·aid 미기입)까지 구제 |

- ③은 **추가 승인 전용** — 차단에는 쓰지 않는다(기존 동작의 순수 상위집합, 오판으로 주입이 줄 위험 0).
- 조합테스트는 양 진영이 다 유저 구성이라 팀 게이트를 **우회**(retaddr로 판별된 화면 경기 한정).
- pid(내 팀 id)는 InGame + 관리틱(server_state) 양쪽에서 확보(어느 쪽이 먼저든).

## 5. TN — 대회 배경 경기 디스크립터 (v2.7.4~v2.8.0에서 규명·연결)

대회(리그) 배경 경기는 rayon worker가 launcher를 부른다. 그 **호출자 프레임 안에 매치 실행 레코드**가 있다:

- launcher 진입 rsp에서 `caller_rbp = rsp+0x88` → `cfg = [rbp+0x1cdc0]`, `set_end = [rbp+0x1cce0]`,
  `db = [rbp+0x1cde8]`(= 서버 db, 검증①).
- `cfg+0x2a0/+0x2d0`의 해시맵(엔트리 0x160)을 역스캔해 **set_end가 세트 Vec 범위에 드는 레코드**를
  특정(검증②) + 키 자기일치·미완료·맵바이트(검증③).
- 레코드 `+0x140/+0x148` = 두 팀 id. 세트 side 바이트(`set+0xf8`)로
  **side0(blue) 팀 = `rec+0x140+(sb^1)×8`** (정적 RE로 확정, 인게임 NG=0 상주 감시).
- 캡처 결과 `(seed → side0팀, side1팀)`를 16슬롯 링 테이블에 게시 → buy 때 provider seed로 조회.

화면 경기·솔로랭크 배경은 이 경로가 아니다(솔로랭크 레코드엔 팀 id가 없음 — 조사로 확정).

## 7. 안전장치

- 모든 raw 포인터 읽기 = **VEH 보호**(`safe_read_*`) — stale 포인터여도 크래시 없이 None.
- launcher detour는 최소 본문(스택 91KB 함수라 format!/락/파일IO 금지 — 원자연산만).
- 버전 게이트: exe 크기 불일치 시 훅 전체 미설치(조용한 오동작 방지).
- 팀 판정 실패(None) = **주입 안 함**이 기본값 — 오염 방지가 주입보다 우선.

# tfm2_item_tactics — 동작 원리 (v2.8.1 · 게임 0.5.4)

> 실제 시간 순서(게임 켜짐 → 전술 지정 → 경기 시작 → 구매 → 화면 표시)대로 설명한다.
> RVA 값은 **0.5.4 기준**이고 패치마다 바뀐다 — 정본은 소스의 상수(`lib.rs`·`ui_inject.rs`).
> English version: `HOW_IT_WORKS.md`.

## 0. 게임이 켜질 때 — 모드 준비

1. **버전 게이트**: exe 크기가 0.5.4와 다르면 아무 훅도 설치하지 않고 스스로 꺼진다
   (`version_gate.txt`에 기록). 어긋난 주소로 몰래 오동작하는 것을 막기 위한 최우선 안전장치.
2. **바이트패치 2곳** (slots=4일 때): ①게임의 "아이템 3개 갖고 있으면 그만 산다" 비교 상수를
   3→4로 (`cmp [athlete+0x448], 3`) ②buy resolver의 슬롯 한계 분기(jbe) 확장. 이 둘로 게임이
   4번째 아이템을 "사도 되는 것"으로 취급하게 된다.
3. **훅 설치**: 매 프레임 post_update에서 설치 상태를 확인하며, launcher처럼 다른 모드(serpen)와
   겹치는 진입부는 **먼저 설치하지 않고 상대 훅이 나타나길 기다렸다가 체인**으로 붙는다
   (외부 훅의 점프 타깃을 우리 트램폴린에 담아 둘 다 순차 발화). 설치는 1회 확정, 이후 1초 주기
   자가복구 점검만.
4. **모드 아이템 레지스트리**: 게임 DB에서 비바닐라 아이템 배열을 스캔해 카탈로그를 만든다
   (`MOD_REGISTRY`). ⚠새 세이브는 저장 후 게임을 재시작해야 모드템이 DB에 병합되므로, 스캔은
   실패 시 최대 500회 재시도 + 실패 사유를 `item_tactics_registry.txt`에 남긴다.
5. **내 팀 id(pid) 확보**: InGame 화면과 관리틱(server_state) 두 경로에서 — 어느 쪽이 먼저 잡히든
   사용. pid로 내 팀 선발 로스터(`MY_ATHLETES` = db.team(pid).last_starting의 athlete_id 5개)를 게시.

## 1. 유저가 전술 화면에서 아이템을 지정할 때

1. 전술/훈련 화면이 로드되는 순간 **UI 로더·파서 훅**이 행마다 4번째 슬롯 노드를 **append 주입**
   (다른 모드가 넣은 노드를 지우지 않도록 replace가 아니라 append + 런타임 좌표 조정).
2. 슬롯 드롭다운의 옵션은 게임 함수(`FN_DD_SETOPT`)로 구성한다: 바닐라 6스탯 + Auto(맡김) +
   **활성화된** 아이템 모드의 아이템들(비활성 모드는 `ModItemEntry+0x190` 플래그로 제외).
   라벨은 게임 i18n 참조(`#asset/base/text/...`)라 언어 설정을 따라 자동 현지화된다.
3. 유저가 고르면 모드가 (챔피언, 슬롯) → 아이템 지정을 스냅샷에 반영하고
   **`item_tactics_sel.txt`에 영속**한다. 저장 포맷은 인덱스가 아니라 **카테고리 번호(1~6) 또는
   아이템 key 문자열** — 나중에 모드 on/off로 목록이 바뀌어도 지정이 어긋나지 않는다.
   조합테스트 화면에서의 지정은 **진영(블루/레드)별 별도 키**로 저장돼 일반 경기와 섞이지 않는다.
4. 이 시점엔 게임에 아무 일도 일어나지 않는다 — 지정은 "예약"일 뿐이고, 실제 개입은 경기 안에서만.

## 2. 경기가 시작될 때 — "이게 무슨 경기인지" 판별

모든 경기(sim)는 화면·배경 가리지 않고 하나의 게임 함수(**launcher**)로 시작된다. 우리 detour가
경기 시작마다 1회 돌면서, **누가 launcher를 불렀는지(retaddr)** 로 경기 종류를 가른다:

| 콜러(retaddr) | 종류 | detour가 하는 일 |
|---|---|---|
| 씬빌더 ×2 | **화면 경기**(관전/내 경기) | 그 경기의 **seed(r8)를 `LIVE_SEED`로 캡처** — 이후 buy에서 "화면 경기 sim" 식별 열쇠 |
| 조합테스트 ×2 | 화면 경기(본경기/기록 다시보기) | seed 캡처 + `COMPTEST_MATCH` 플래그(팀 게이트 우회용) |
| worker.rs | **대회(리그) 배경 sim** | **TN 캡처** — 아래 §3 |
| solo_rank / 메타 sim 등 | 기타 배경 sim | 아무것도 안 함(멤버십 판정만으로 충분) |

직후 게임이 RNG provider를 만들 때 **seed-ctor 훅**이 "지금 만든 provider가 `LIVE_SEED`의
것이면" 그 포인터를 `RENDER_PROVIDER`로 기억한다. seed는 provider 안(`+0xeb28`)에 초기값으로
남아 있어서, 나중에 buy가 들고 오는 provider와 대조하면 **어느 sim의 구매인지** 정확히 안다.

## 3. TN — 대회 배경 경기는 시작 시점에 "누구 vs 누구"까지 알아낸다

> **TN = Tournament(대회) 약자.** 코드 접두어(`TN_*`, `tourn_capture`)를 문서에서도 그대로 쓴다.

대회 배경 sim은 rayon worker가 launcher를 부르는데, 그 **호출자 스택 프레임 안에 매치 실행
레코드**가 있다. launcher 진입 rsp에서 `caller_rbp = rsp+0x88`을 역산해:

1. `cfg = [rbp+0x1cdc0]`(배경 sim 상태), `set_end = [rbp+0x1cce0]`(지금 돌 세트블록 끝),
   `db = [rbp+0x1cde8]`을 읽고 — **검증① db가 우리가 아는 서버 db와 일치**해야 진행.
2. `cfg+0x2a0/+0x2d0`의 해시맵(정규 시즌/포스트시즌)을 역스캔해 **set_end가 세트 Vec 범위에
   정확히 드는 레코드**를 특정(검증②) + 매치키 자기일치·미완료·맵바이트(검증③).
3. 레코드 `+0x140/+0x148` = 두 팀 id. 세트의 진영 바이트(`set+0xf8`)로
   **side0(blue) 팀 = `rec+0x140+(sb^1)×8`** (정적 RE로 확정식 증명 + 인게임 NG=0 상시 감시).
4. 결과 `(seed → side0팀, side1팀)`을 **16슬롯 링 테이블에 게시**. 이게 §4의 세 번째 판정 소스다.

스캔이 안 맞으면 그냥 포기(=기존 동작) — TN은 틀려도 잃을 게 없는 구조다.

## 4. 경기 중 선수가 아이템을 사려는 순간 — 판정과 주입 (핵심)

게임 sim에서 선수가 구매를 시도할 때마다 **buy 함수**가 불리고, 우리 detour가 원본보다 먼저 돈다:

**(a) 이 구매가 어느 경기 것인가** — buy 인자의 provider(r9)에서 seed를 읽어
`LIVE_SEED`와 같으면 화면 경기, TN 테이블에 있으면 대회 배경 경기, 둘 다 아니면 기타 배경.

**(b) 이 선수가 내 팀인가** — 판정 소스 3개의 **OR 결합(하나만 걸려도 통과)**:

| 소스 | 커버 | 원리 |
|---|---|---|
| ① scene side | 화면 경기 | db의 매치 정보(두 팀 id + is_team1_blue) 직독으로 내 진영 계산 → 선수의 진영(`athlete+0x810`)과 대조. ②와 1/256 샘플 교차검증 상주 |
| ② aid 멤버십 | 배경 전반 | 선수의 `athlete_id(+0x800)` ∈ `MY_ATHLETES` |
| ③ TN | 대회 배경 | §3 테이블에서 내 팀 side를 얻어 선수 진영과 대조 — ②가 놓치는 **교체 출전·athlete_id 미기입 선수까지 구제** |

- ③은 **승인 전용**(차단엔 안 씀) — 기존 동작의 순수 상위집합이라 오판으로 주입이 줄 일이 없다.
- 조합테스트는 양 진영이 다 유저 구성이므로 팀 게이트 자체를 우회(단, 화면 경기로 확인된 것만).
- 판정 불가(None) = **주입 안 함.** 남의 팀 오염 방지가 항상 우선.
- 내 선수가 아니면 여기서 즉시 원본으로 통과(배경 buy의 ~94%가 이 조기탈출로 빠진다 — 비용은
  VEH 읽기+해시셋 조회 수준).

**(c) 주입** — 내 선수로 확정되면 그 선수의 **build Vec(목표 빌드 배열, `+0x480/488/490`)** 을 덮어쓴다:

- 슬롯 0~2: 지정 아이템의 카탈로그 인덱스. 단 **`owned ≤ 슬롯번호`인 칸만** — 이미 산 아이템은
  절대 건드리지 않는다.
- 슬롯 3: 지정이 있으면 그 값. Auto면 **게임의 아이템 신경망을 shadow-call**(5-feature 채점)해서
  후보 중 최고점 아이템을 넣는다.

**(d) 구매는 게임이 한다** — 모드가 바꾸는 건 "목표"뿐이다. 게임의 buy resolver가 그 목표를 향해
t0→t4 티어를 정상 골드·정상 타이밍으로 빌드업한다(§0의 바이트패치가 4개 보유를 허용).

## 5. 경기 화면에 보여줄 때

게임 UI는 아이템 칸을 3개만 그린다(노드명 하드코딩). **GameView update 훅**이 매 프레임 뷰모델을
직독해 4번째 아이템의 **아이콘 노드를 직접 그리고**, 마우스오버 시 **게임의 툴팁 show 함수를
인자 11개 그대로 호출**해 정품 툴팁을 띄운다(게임 코드 수술 없음 — 무패치 방식).

## 6. 상시 자가진단

`item_tactics_registry.txt`에 판독 규칙까지 포함해 상주 기록: pid·로스터 게시 상태, 게이트 통과/
차단 카운트(★"판정불가로 막힘"이 0이어야 정상), scene↔멤버십 교차검증(불일치 0 필수),
TN 스캔 성공률·side 매핑 NG(0 필수)·TN 구제 횟수. **주입이 안 된다는 제보는 이 파일 하나로
원인 구간이 갈린다.**

# community_reaction_mod — 확장 export 포맷 명세 (HTML 파싱용)

> 대상: `mods/community_reaction_mod/latest_match.js` 를 소비하는 HTML/JS 개발자.
> 이 문서는 **개조판 dll이 새로 추가한 출력**만 다룬다. 원작 섹션(챔피언 통계/리그 명칭/상대 전적/
> `--- 현재 리그 순위 (Standings) ---`/세트 상세/POG)은 원작 형식 그대로이며 변경 없음.
> 기준 dll: 2026-07-03 빌드 (1,115,648B 이후).

## 0. 컨테이너 (원작 그대로)

```js
var latestMatchData = {"summary": "<텍스트 전체>", "series_id": N, "is_series_finished": true|false, "date": "YYYY-MM-DD HH:MM:SS"};
```
- 추가 정보는 전부 `summary` 문자열 안의 **텍스트 섹션**이다. 줄 단위(`\n`) 파싱을 권장.
- 게임(커리어 화면)에서 **3초마다 상시 재출력**된다. 경기 종료 순간에만 쓰는 게 아님.
- 섹션 순서: (원작 앞부분) → `--- 현재 리그 순위 (Standings) ---`(원작) → **`--- 경기 구분 상세 (추가 정보) ---`(신규)** → **`--- 경기 하이라이트 ... ---`(신규)** → `====== 메인 매치 ...`(원작 세트 상세).

## 1. 섹션: `--- 경기 구분 상세 (추가 정보) ---`

### 1-1. 경기 구분 라인 (항상 1줄)

```
경기 구분: <값>
```
값의 종류 (전부 나열):
| 값 패턴 | 의미 |
|---|---|
| `연습 경기 (스크림/비공식전 — 리그 순위와 무관)` | 연습/스크림 |
| `자국 리그 정규 시즌 — <리그명>` | 정규시즌 |
| `리그 플레이오프 — <리그명> / <라운드 라벨>` | 리그 플옵 |
| `국제전 [<대회명>] — <스테이지>` | 국제전 |
| `판별 불가(진행 정보 부족) — 참고용 자국 리그(<리그명>) 순위` | 폴백 |

- 대회명: `챌린저스 이스턴` `챌린저스 웨스턴` `마스터스` `챔피언스` (미지 대회는 영문 원명).
- 스테이지: `스위스 스테이지` | `조별 리그 (n조)` | (녹아웃) `결승전` / 8매치면 리그와 같은 라운드 라벨 / 그 외 `녹아웃 스테이지 n번째 경기 (총 m경기)`.
- 리그 라운드 라벨(8매치 더블엘리): `플레이오프 승자조 1라운드` `플레이오프 패자조 1라운드` `플레이오프 승자조 결승` `플레이오프 패자조 2라운드` `플레이오프 패자조 결승 (결승 진출전)` `결승전`. 8매치가 아니면 `플레이오프 n번째 경기 (총 m경기)`.

### 1-2. 리그 정규시즌일 때

```
리그 진행도: {치른 매치}/{총 매치} 매치

[리그 순위표]
 - 1위: DFM Academy (17승 1패 | 세트득실: +29)
 - 8위: Ground Zero (10승 8패 | 세트득실: +5) ◀ 우리 팀
```
순위행 정규식 (JS):
```js
/^\s*-\s*(\d+)위:\s*(.+?)\s*\((\d+)승 (\d+)패 \| 세트득실: ([+\-]?\d+)\)(\s*◀ 우리 팀)?\s*$/
```
리그 플레이오프일 때는 `(아래 순위는 정규시즌 최종 순위)` 안내 후 같은 `[리그 순위표]`.

### 1-3. 국제전 — 조별 리그일 때

```
[마스터스 1조 순위]
 - 1위: T1 (3승 0패 | 세트득실: +6)
...
[마스터스 2조 순위]
 - 1위: DFM Academy (2승 0패 | 세트득실: +4) ◀ 우리 팀
```
헤더 정규식: `/^\[(.+?)\s+(\d+)조 순위\]$/` — 조가 여러 개 연속으로 나온다. 행은 1-2와 동일.

### 1-4. 국제전 — 스위스 스테이지일 때

```
[마스터스 스위스 스테이지 현황 (3승 진출 / 3패 탈락)]
[3-0] — 녹아웃 진출
 - T1 (세트득실 +6)
 - Garnet Fiends (세트득실 +4)
[2-1]
 - DFM Academy (세트득실 0) ◀ 우리 팀
[0-3] — 탈락
 - ...
```
- 버킷 헤더: `/^\[(\d+)-(\d+)\](?:\s*—\s*(.+))?$/` — 그룹3 = `녹아웃 진출` | `탈락` | 없음. 승수 내림차순 정렬돼 나옴.
- 팀 행: `/^\s*-\s*(.+?)\s*\(세트득실\s*([+\-]?\d+)\)(\s*◀ 우리 팀)?\s*$/`

## 2. 대진표 블록 (경기 구분 상세 섹션 안)

두 종류, 헤더만 다르고 매치 행 문법은 동일:

```
[플레이오프 대진표] 형식: <형식 라벨> | 구조: <구조 라벨>
[M1] 2027-04-15 | BO5 | 정규 1위 시드(DFM Academy) vs 정규 4위 시드(Ground Zero) | 종료 3:2 → 승자 DFM Academy
[M5] 2027-04-24 | BO5 | M1 승자(DFM Academy) vs M2 승자(CTBC Flying Oyster) | 진행중
[M8] 2027-05-02 | BO5 | M5 승자(미정) vs M7 승자(미정) | 예정
```
```
[스위스 라운드 매치] 형식: ... | 구조: ...
[M1] 2027-05-14 | BO1 | T1 vs Bilibili Gaming | 종료 1:0 → 승자 T1
```

- **출력 조건**: `[플레이오프 대진표]` = 리그 플옵 목록 또는 국제전 녹아웃 목록이 비어있지 않을 때(정규시즌 말미에 미리 생성된 플옵도 나옴). `[스위스 라운드 매치]` = 스위스 스테이지일 때(생성된 라운드까지의 전 매치). **둘이 한 summary에 공존 가능**(녹아웃 진행 중 스위스 이력) — 반드시 자기 헤더 라인 아래의 연속된 `[M..]` 라인만 스코프 파싱할 것.

### 2-1. 매치 행 문법

```
[M{n}] {YYYY-MM-DD} | BO{k} | {슬롯1} vs {슬롯2} | {상태}
```
정규식: `/^\[M(\d+)\]\s*([\d\-]+)\s*\|\s*BO(\d+)\s*\|\s*(.+?)\s+vs\s+(.+?)\s*\|\s*(.+)$/`
- `{n}` = 대진 목록 내 1-기반 순번(같은 블록 안에서 안정적 식별자).
- 상태: `예정` | `진행중` | `종료 {a}:{b} → 승자 {팀명}` (`a:b`=슬롯1:슬롯2 세트스코어).

### 2-2. 슬롯 문법 (팀 자리)

| 패턴 | 의미 |
|---|---|
| `{팀명}` | 확정 팀 |
| `M{k} 승자({팀명}\|미정)` | k번 매치의 승자 (승자조 간선) |
| `M{k} 패자({팀명}\|미정)` | k번 매치의 패자 (패자조 간선 → 있으면 더블엘리) |
| `정규 {r}위 시드({팀명})` / `정규 {r}위 시드` | 정규시즌 r위 시드 (팀명 해석은 가능할 때만) |
| `리그 {r}위 시드` | 리그 순위 시드 |
| `조시드[a, b, c]` | 조별 순위 시드 — 튜플 의미 미검증, raw 표기 |
| `대회시드[a, b]` | 시드 해석 실패 폴백(raw) |

### 2-3. ⚠ 핵심 함정: 간선 소실

게임은 **어떤 매치의 승자가 확정되는 순간, 그 승자를 참조하던 슬롯을 확정 팀명으로 덮어쓴다.**
즉 `M1 승자(DFM Academy)` 표기는 다음 export부터 그냥 `DFM Academy`가 된다.
브래킷 그래프(연결선)를 그리려면:
1. **참조가 살아있을 때(이르면 정규시즌 말미부터) 간선을 캐시**해 두거나,
2. 리그 8매치 더블엘리 고정 구조를 이용: `M1/M2=승자조 1R → M3/M4=패자조 1R → M5=승자조 결승 → M6=패자조 2R → M7=패자조 결승 → M8=결승`,
3. 날짜 간격(2일 이상 벌어지면 다음 라운드)으로 보조 추정.

### 2-4. 형식/구조 라벨

- 형식(설정값 기반): 리그 = `리그 플레이오프 규칙={더블 엘리미네이션|토너먼트(싱글 엘리미네이션)} [raw l,c,g]`,
  국제전 = `국제대회 규칙={토너먼트(싱글 엘리미네이션)|더블 엘리미네이션} / 그룹 형식={조별 리그|스위스 스테이지} [raw l,c,g]`.
  `[raw ...]`는 진단용 — **파싱 시 무시 권장** (`/\s*\[raw[^\]]*\]/` 제거).
- 구조(간선 기반 추정): `더블 엘리미네이션형(패자조 간선 존재)` | `녹아웃형(싱글 엘리미네이션 계열)` | `전 경기 확정(간선 정보 소실 — 형식은 설정값 참조)` | `고정 대진형(조별/스위스 라운드)`.

### 2-5. 스위스 라운드 번호 계산법 (매치 행엔 라운드가 없음)

매치 목록 순서대로 각 팀의 (승+패)를 누적하면서, 각 매치의 라운드 = `max(두 팀의 지금까지 경기 수) + 1`.
종료된 매치만 전적에 반영. (날짜 기반보다 정확 — 같은 날 여러 라운드여도 안전.)

## 3. 섹션: `--- 경기 하이라이트 (직접 관전한 세트 프레임 분석) ---`

```
--- 경기 하이라이트 (직접 관전한 세트 프레임 분석) ---
연속킬 / 다인 궁극기 / 포탑 데스 / 골드 대역전 등 명장면 목록입니다.
[2세트 하이라이트 (킬스코어 9:5)]
 - [04:20] reversive 궁극기 — 적 3명 적중!
 - [07:11] Lambert(백마술사) 포탑에 맞아 사망!
[관전 세트 #3 (킬스코어 10:5)]
 - ...
```

- **직접 관전(시청)한 세트만** 수집된다. 하이라이트가 하나도 없으면 **섹션 자체가 생략**됨.
- 블록 헤더: `[{n}세트 하이라이트 (킬스코어 {b}:{r})]` — 세트 번호 특정 성공.
  폴백 `[관전 세트 #{k} (킬스코어 {b}:{r})]` — 리플레이 등록 전(수 초) 일시 표기, 다음 export에서 세트 번호로 바뀜.
- 라인 공통: ` - [{mm:ss}] {내용}` — `mm:ss` = 게임 내 경과 시간.
- 내용 종류 (전부 나열):

| 패턴 | 의미 |
|---|---|
| `{선수}({챔피언}) {더블킬\|트리플킬\|쿼드라킬\|펜타킬\|{n}연속킬}!` | 10초 내 연속킬 |
| `{선수} 궁극기 — 적 {n}명 적중!` | n인 궁 (3명 이상) |
| `{선수} 광역 스킬 — 적 {n}명 적중!` | 광역 스킬 (4명 이상) |
| `대규모 한타! 궁·스킬 연쇄 {m}회 — {선수} 궁({n}명)·{선수} 스킬({n}명)·…` | 10초 내 궁/스킬 연쇄 병합 |
| `{선수}({챔피언}) 포탑에 맞아 사망!` | 포탑/처형 데스 |
| `{블루\|레드}팀, 최대 {X}G 골드 열세를 뒤집고 역전승! (최대 열세 시점 {mm:ss})` | 10,000G+ 역전승 |

- 적중 카운트는 챔피언 간 스킬 교전만(미니언/포탑 피해·분신 제외), 시전자 귀속 기반.

## 4. 참고 구현

이 포맷의 파서+렌더러 참조 구현이 이미 있음 — 개조판 `TFA2_gallery.html`의 다음 함수들:
`parseMatchBlock`(블록 스코프 [M..] 파싱), `parseBkSlot`(슬롯), `parseSwissStandings`(스위스 버킷),
`parseGroupTables`(조별), `parseBracket`(통합 진입점), `bkStructMerge`(간선 캐시, localStorage),
`renderBracketCanvas`(더블엘리 브래킷 SVG), `renderSwissCanvas`(스위스 라운드 컬럼), `renderGroupsCanvas`(조별 컬럼).
그대로 이식하거나 참고하면 된다.

## 5. 버전 유의사항

- `경기 구분: 자국 리그 정규 시즌 ...`일 때는 (미리 생성된) 플레이오프 대진표가 함께 나올 수 있음 — 표시 여부는 소비측 판단.
- 원작 섹션의 `대회 형태:` 라인(원작 문법)은 그대로 유지되므로 기존 파서는 깨지지 않음. 신규 파서는 `경기 구분:` 라인을 쓰는 것을 권장(더 정확).
- 형식 라벨의 `[raw l,c,g]`는 이후 버전에서 제거될 수 있음 — 의존 금지.
- ⚠ **`is_series_finished` 산출 함정 (2026-07-15 수정)**: 시리즈 승수는 **blue/red 슬롯이 아니라 실제 팀 id 기준**으로 집계해야 한다. TFM2는 세트마다 패자가 진영을 고르므로(고정 스왑 아님) 한 팀의 승리가 blue/red 슬롯에 흩어진다. 슬롯 기준으로 세면 2-0 스윕이 1-1로 오판돼 `is_series_finished`가 영영 `false`가 되고, 소비측(갤러리)의 시리즈 종료 자동 반응생성(`is_series_finished && !generatedSeriesIds.has(sid)`)이 누락된다(간헐적 — 패자 진영선택이 우연히 한 슬롯에 몰리면 맞음). dll은 `winner_team_id = blue_team_win ? blue_team_id : red_team_id`로 팀별 귀속 집계하도록 고쳤다.
